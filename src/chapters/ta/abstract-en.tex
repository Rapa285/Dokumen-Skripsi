	Electronic Health Records (EHR) are a fundamental component of healthcare service delivery in Indonesia. Indonesian Minister of Health Regulation No.~24 of 2022 mandates all healthcare facilities to implement EHR while guaranteeing the confidentiality, integrity, and availability of patient data. To address this requirement, prior research developed DecMed, a decentralized EHR management framework built on the IOTA Distributed Ledger Technology (DLT), Proxy Re-Encryption (PRE), and IPFS. Although DecMed successfully addressed access control, its existing activity logging mechanisms do not constitute an adequate audit log: event recording is fragmented across individual components without a central collector, event coverage is narrow, old records can be overwritten in violation of the append-only principle, record formats are unstandardized, and digital evidence is vulnerable to loss due to the data-pruning mechanism inherent in DLT networks.

	This final project develops the Audit Log Service (ALS), a standalone backend service integrated into the DecMed architecture. The design begins with a STRIDE threat analysis of DecMed, yielding 25 threats mapped to 13 audit event types (EV1--EV13). Each event source (\textit{Patient Client}, \textit{Hospital Client}, \textit{Ministry Client}, and PRE Server) transmits audit events to ALS encapsulated as an \texttt{EncryptedSignedEvent}: the event payload is encrypted using AES-256-GCM with a per-message random session key, the session key is wrapped using ECIES over P-256 with the ALS public key, and the ciphertext is signed using the actor's \texttt{IotaKeyPair} under an Encrypt-then-Sign pattern. Before transmission, each encrypted and signed event is first persisted to a file-based outbox queue (\texttt{AlsQueue}) to guarantee delivery even in the presence of transient network failures. Upon receipt, ALS verifies the \texttt{IotaSignature} over the ciphertext, decrypts the payload, and constructs a structured \texttt{AuditRecord} containing two distinct timestamps: \texttt{source\_timestamp}, recording the time of the event according to the sending component's clock, and \texttt{timestamp}, recording when ALS formed the record. SHA-256 hash-chaining is applied across records so that every \texttt{AuditRecord} is cryptographically bound to all preceding records, making any modification at any position in the chain detectable. Periodically, ALS rotates the active log file, uploads the archive to the IPFS Cluster with pinning to prevent garbage collection, and publishes the rotation metadata as a frozen object in an IOTA Move smart contract via DecMed's existing Gas Station Server.

	Implementation and testing results demonstrate that ALS successfully aggregates audit events from all DecMed components into a single centralized repository, records all 13 event types covering every identified STRIDE threat, and enables tampering detection through hash-chaining at the audit record level. A full end-to-end test (P-INT-01) using an EV4 (Medical Record Access) scenario proves that from a single record the system can establish who accessed which data, when, and under what authorization; that tampering at any position in the chain is detected through a hash-mismatch domino effect; and that archived log files can be retrieved from IPFS with byte-for-byte integrity. Long-term data retention is ensured through a combination of IPFS pinning and immutable on-chain metadata storage. Three limitations are explicitly acknowledged: decrypting event content from archived files requires the ALS private key; cross-record search and filtering facilities are not yet implemented; and non-repudiation based on \texttt{IotaKeyPair} holds only as long as the actor's private key has not been compromised or rotated between the time of the event and the time of investigation. ALS does not alter any of DecMed's existing business logic or core functionality, and reuses the existing IPFS and IOTA infrastructure without introducing new storage dependencies.
